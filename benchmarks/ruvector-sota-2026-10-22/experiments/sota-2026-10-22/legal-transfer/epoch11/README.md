# Epoch11 frozen data identities

This directory contains a source-licensed, internal three-predicate original ContractNLI NDA pilot. It is not a score on full LegalBench, current JevBench300 or ClaimBench. No model, native inference, fitting or benchmark scoring was executed by this data worker.

TRAIN and calibration are empty. DEV has24 queries from8 newly drawn original-train documents. Existing epoch9 confirmation48/16groups is preserved byte-for-byte, remains project-model-unused, and is referenced by path and SHA rather than relabelled or redrawn. No confirmation JSON/labels were inspected; its file was hashed and its separate label-free identity allowlist was used. A public source is not a sealed test and does not prove absence of upstream pretraining contamination.

The registry extends the hash-verified epoch10 exclusion history:165 original-train groups are already exposed,16 groups are reserved for existing confirmation, and242 were eligible. The fixed text/ID-only SHA256 draw takes the first8 using an epoch11 salt, with no label, outcome or length stratification and no redraw. Exact IDs, normalized source texts, and official DEV/TEST collision hashes are excluded. Roles froze before the selected DEV gold labels were projected. After the draw234 groups remain unreserved; after any actual phase1 attempt, the declared8 DEV groups conservatively become permanently exposed, yielding173 exposed groups. A confirmation process attempt retires all48/16 groups even if it fails before a successful prediction. These exposure rules are distinct from actual request completion counts.

Old public183, easy48, Legal96, original-dev confirmation96f018 and all prior project DEV sets remain DEV forever. Exact/fuzzy document versions and historical source uncertainty are not fully ruled out.

`build.py --source /path/to/hash-verified/original-train.json --output-dir /unused/output` recreates DEV24 and its label-free allowlist from only the builder, eligibility registry, draw plan, document selection, and separately restored exact source. It does not require or read confirmation labels. `validate.py` checks frozen bytes and eight mutation controls. `isolated-replay-validation.json` records a clean two-output byte-identical rebuild.

Only `input.state` and `input.questions` may reach inference. Gold, record IDs, source groups, split roles, provenance and source annotations are excluded. Binary gold is Yes only for original Entailment; Contradiction and NotMentioned map to No, while original three-way labels are retained for diagnostics. Document groups are the statistical bootstrap unit.

Public receipts/extracted aggregates are retained; raw pages/examples and nested replay output directories are excluded by `publication-files.json`.
